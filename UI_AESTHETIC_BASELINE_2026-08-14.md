# BASISForum UI Aesthetic Baseline

## Captured surfaces

The baseline includes the dark desktop homepage, Archive and Sakura desktop discussion pages, and dark and Archive mobile views. It was captured from the deployed application at 1440px desktop and 390px mobile widths.

## Objective findings

| Surface | Finding | Objective consequence |
|---|---|---|
| Desktop campaign slot | The default cinematic configuration has a large blank media cell without a visible media treatment, while the editorial copy and CTA are compact. | The top slot reads partly unfinished and its intended asymmetry lacks a deliberate visual anchor. |
| Archive mobile campaign | Dark campaign title text is too close to the campaign background in the current default cinematic option, causing a weak title hierarchy. | The most important campaign text fails the intended contrast hierarchy in a light display mode. |
| Mobile thread index | Category and reply columns are visually faint compared with title text, and the control/header transition is dense. | Metadata is difficult to scan at a glance, even though no horizontal overflow occurs. |
| Desktop index | The grid is disciplined and readable, but the section-header labels, sort control, and table header compete with similar visual weights. | The primary scan order is less obvious than the content hierarchy should be. |

## Constraints

All refinements must preserve BASISForum’s black/white editorial character, zero radius, thin rules, centralized token use, mobile no-overflow result, and the configured campaign templates. Changes should be retained only when they correct a measurable contrast, scan-order, responsive-density, or consistency problem.
