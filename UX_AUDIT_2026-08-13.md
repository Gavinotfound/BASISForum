# BASISForum Live UX Audit — 2026-08-13

## Reviewed Routes

| Route | Observed State | Priority Finding |
|---|---|---|
| `/` | The Swiss thread-grid composition is visibly present: compact editorial header, search, defined column rules, category markers, and right-aligned numeric metadata. | Maintain the grid; future improvements should emphasize semantic accessibility and realistic empty/error states rather than add visual chrome. |
| `/login` | The page is functional and visually minimal, but the narrow centred login form has no surrounding structural rule or editorial context. The shared implementation still uses `Card` components even though global overrides remove their card styling. | Replace the semantic card wrappers with purpose-built rule-based form layouts, clarify the secondary “Forgot Password?” action, and retain visible pending/error feedback. |

## Design Compliance Notes

The deployed site uses the dark Swiss palette, hard edges, mono metadata, and thread-grid dividers. The next focused visual improvement should remove dead card/paper abstractions from authentication and profile forms, making the implementation directly express the strict no-card, zero-radius design specification.

| `/profile` | The functional content is cleanly arranged as a desktop two-column editor plus learning metrics. The present `Paper` elements are globally neutralized, so the page appears mostly compliant, but its component choices and explicit rounded styling still contradict the system. | Replace `Paper` wrappers with semantic `Box` sections and add deliberate rule lines; improve input labels by adding explicit `id`/`htmlFor` pairings and retain the existing grid. |
